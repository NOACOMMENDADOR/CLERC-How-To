Purpose

Package and deploy desktop software to company computers through Microsoft Intune using the Win32 app format. This method works for both .msi and .exe installers and ensures that apps automatically install on any device enrolled in Intune when assigned as Required.

Section 1 Download the Win32 Content Prep Tool

1.1

Download and Extract the Tool

The Win32 Content Prep Tool is a Microsoft utility that converts installers into the .intunewin format Intune requires. You only need to download this once per admin machine.

  1. Go to github.com/microsoft/Microsoft-Win32-Content-Prep-Tool
  2. Click the green Code button, then click Download ZIP.
  3. Extract the ZIP file. Inside you will find IntuneWinAppUtil.exe.
  4. Keep this file in a permanent location on your admin machine (e.g., C:\IntuneTools\). No installation is required.
💡
One-time setup: This tool only needs to be downloaded once. Keep it in a consistent location so it's ready whenever you need to package a new app.

Section 2 Prepare the Installer

2.1

Set Up the App Folder

Each app you want to deploy needs its installer file placed in its own dedicated folder.

  1. Create a folder for the app:
Example: C:\IntuneApps\Chrome
  1. Download the enterprise installer for your software and place it in that folder.
Example: Google Chrome
  1. Download the Chrome enterprise .msi from chromeenterprise.google/download
  2. Select the 64-bit .msi installer.
  3. Place the downloaded file (e.g., googlechromestandaloneenterprise64.msi) in your app folder.
⚠
Each app should have its own separate folder containing only its installer file. Do not mix multiple installers in one folder.

Section 3 Package the Installer

3.1

Run the Content Prep Tool

  1. Open the folder where you extracted the Win32 Content Prep Tool.
  2. Double-click IntuneWinAppUtil.exe to launch it.
  3. Answer the prompts:
Source folder: C:\IntuneApps
Setup file: googlechromestandaloneenterprise64.msi
Output folder: C:\IntuneApps\Output
Catalog folder? N
  1. The tool will process for a few seconds and create a .intunewin file in your output folder.
  2. Repeat steps 2-4 for each additional installer you need to package.

Section 4 Add the App to Intune

4.1

Create the Win32 App

  1. Sign in to intune.microsoft.com
  2. Navigate to Apps > All apps > Create
  3. For App type, select Windows app (Win32), then click Select.
  4. Click Select app package file, browse to your .intunewin file, and click OK.
4a

App Information

The Name, Description, and Publisher fields will auto-fill from the installer metadata (for .msi files). Review these fields and click Next.

💡
You may need to manually enter the publisher name if it doesn't auto-populate.
4b

Program

For .msi installers

Intune will auto-populate the install and uninstall commands:

Install: msiexec /i "filename.msi" /qn
Uninstall: msiexec /x "filename.msi" /qn

Leave these as-is. They are correct.

For .exe installers

You must manually enter the commands. The silent install flag varies by software. Common examples:

setup.exe --silent
setup.exe /S
setup.exe /quiet
💡
Check the software vendor's documentation for the correct silent install flag for .exe installers.

Set Install behavior to System. Leave remaining fields as defaults. Click Next.

4c

Requirements

  • Operating system architecture: Check 64-bit
  • Minimum operating system: Select the lowest OS version in your fleet (e.g., Windows 10 1607)

Click Next.

4d

Detection Rules

Detection rules tell Intune how to determine whether the app is already installed on a device. This prevents reinstalling software that is already present.

For all installers (.msi and .exe), use a file-based detection rule:

  1. Set Rules format to Manually configure detection rules.
  2. Click Add.
  3. Set Rule type to File.
  4. Path: Enter the install directory (e.g., C:\Program Files\Google\Chrome\Application)
  5. File or folder: Enter a file that confirms the app is installed (e.g., chrome.exe)
  6. Detection method: Select File or folder exists.
  7. Click OK, then Next.
⚠
Do not use MSI detection rules, even for .msi installers. MSI product codes are version-specific, so if the app auto-updates itself (as Chrome and many other apps do), the detection rule will stop matching and Intune will try to reinstall.
⚠
Avoid version-numbered paths (e.g., 130.0.2.0) because the path will change when the app updates and the detection rule will break. Use a stable file in the application's root install directory.
💡
To find the correct detection path, check a machine that already has the app installed and note where its main executable lives.
4e

Dependencies and Supersedence

Skip both of these pages. Click Next on each.

4f

Assignments

  1. Under Required, click Add group.
  2. Select your device group (e.g., CLERC Windows Devices) or choose All Devices.
  3. Click Next.
Assignment types explained
  • Required = Intune pushes the app automatically. No user action needed. Use this for standard company software.
  • Available for enrolled devices = App appears in Company Portal for users to install on their own. Use this for optional software.
4g

Review and Create

Review all settings, then click Create. Intune will upload the package and begin deploying it to assigned devices on the next sync cycle.

Section 5 Deployment Timeline

5.1

When Devices Receive the App

After creating the app assignment:

  • Newly enrolled devices will receive the app immediately during their first sync.
  • Existing devices will receive the app on their next Intune policy refresh cycle (approximately every 8 hours).
  • Devices that already have the app installed will be detected by the detection rule and skipped.
⚡
Force immediate sync on a device: Settings > Accounts > Access work or school > Info > Sync

Section 6 Verifying Deployment Status

6.1

Check Install Status

  1. In Intune, go to Apps > All apps.
  2. Click on the app you deployed.
  3. Click Device install status to see which devices have successfully installed the app, which are pending, and which have failed.
