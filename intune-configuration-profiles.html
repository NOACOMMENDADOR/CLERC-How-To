Purpose

This SOP documents the configuration profiles deployed to CLERC workstations through Microsoft Intune. Configuration profiles push device settings automatically to enrolled machines, covering Windows Update management, Wi-Fi connectivity, and other system-level preferences.

This document explains what each profile does, how to create or modify profiles, and potential issues to watch for.

Section 1 Windows Update Policy

The CLERC Update Policy controls how Windows updates are delivered to company devices. It defers updates to avoid bad patches and prevents forced restarts during business hours.

Current Settings

Setting Value What It Does
Quality update deferral 3 days Security patches and bug fixes (released monthly) are delayed 3 days before being offered to devices. This allows time for Microsoft to catch and pull any problematic patches.
Feature update deferral 15 days Major Windows version upgrades (released once or twice per year) are delayed 15 days. These are large updates that can change system behavior, so the deferral lets early adopters find problems first.
Active hours 7 AM - 6 PM Windows will not force a restart for updates during these hours. Restarts for pending updates will only happen outside this window.

Creating or Editing the Update Policy

  1. Sign in to intune.microsoft.com
  2. Navigate to:
    Devices ➜ Configuration ➜ Policies
  3. To edit the existing policy, click on it and select Properties > Edit. To create a new one, click Create > New policy.
  4. Select Windows 10 and later as the platform and Settings catalog as the profile type.
  5. Click Add settings and search for Windows Update for Business.
  6. Configure the deferral periods and active hours as needed.
  7. Assign to your device group and save.

Potential Issues

🔄 Laptops shut down overnight

If a user shuts down their laptop every evening, updates may never get a window to install outside active hours. The device will eventually show a forced restart notification during work. Advise staff to leave laptops on overnight occasionally, or to restart manually when they see an update notification.

🕑 Deferred patches and security risk

The 3-day quality deferral means devices are briefly behind on security patches after each monthly release. For a small organization this is a reasonable tradeoff between stability and security.

📦 Feature update stacking

Feature update deferrals can stack with Microsoft's own gradual rollout. A 15-day deferral on top of Microsoft's rollout schedule could mean devices are several weeks behind on major updates. This is expected and fine for stability.

Section 2 Wi-Fi Profile

The CLERC Office Wi-Fi profile pushes the office wireless network configuration to all enrolled devices. Devices automatically connect to the network when in range without staff needing to enter the password.

ⓘ Wi-Fi profiles use a template-based policy, not the Settings catalog.

Creating or Editing the Wi-Fi Profile

  1. In Intune, go to:
    Devices ➜ Configuration ➜ Policies ➜ Create ➜ New policy
  2. Select Windows 10 and later as the platform and Templates as the profile type.
  3. Select Wi-Fi from the template list.
  4. Enter a name (e.g., CLERC Office Wi-Fi).
  5. Configure the following settings:
    Wi-Fi Configuration
    • Connection name: Enter the network name (this is the label users see in Windows).
    • Wi-Fi name (SSID): Enter the exact network name as your router broadcasts it.
    • Connect automatically when in range: Yes.
    • Security type: Select your router's security type (most commonly WPA/WPA2-Personal).
    • Pre-shared key: Enter the Wi-Fi password.
  6. Skip the Applicability Rules section (leave blank).
  7. Assign to your device group and create.

Potential Issues

🔐 Wi-Fi password changes

If the office Wi-Fi password is changed on the router, you must also update it in this Intune profile. Until the profile is updated, every enrolled device will fail to connect. Update the profile immediately when changing the Wi-Fi password.

📶 Multiple networks

If your office has more than one Wi-Fi network (e.g., a guest network and a staff network), create a separate profile for each one that devices should connect to.

🏠 Remote workers

Devices that are never in the office will receive this profile but simply won't connect to it since the network is not in range. This causes no issues.

Section 3 Adding a New Configuration Profile

Intune supports two types of configuration profiles:

Settings Catalog

A searchable list of individual settings.

Use for:
  • Update policies
  • Power settings
  • Security settings
  • Most new profiles

Templates

Pre-built profile types for specific features.

Use for:
  • Wi-Fi
  • VPN
  • Email
  • Certificates

Using the Settings Catalog

  1. Go to:
    Devices ➜ Configuration ➜ Create ➜ New policy
  2. Platform: Windows 10 and later. Profile type: Settings catalog.
  3. Name the profile.
  4. Click Add settings and search for the setting you need.
  5. Configure the values, assign to your device group, and create.

Using a Template

  1. Go to:
    Devices ➜ Configuration ➜ Create ➜ New policy
  2. Platform: Windows 10 and later. Profile type: Templates.
  3. Select the template from the list (e.g., Wi-Fi, VPN, Email).
  4. Name the profile, configure the settings, assign, and create.
⚠ Always test a new configuration profile on a single device before assigning it to the full device group. Assign it to just your own device first, verify it works, then expand the assignment.

Section 4 Verifying Profile Deployment

Check deployment status

  1. In Intune, go to:
    Devices ➜ Configuration ➜ Policies
  2. Click on the profile you want to check.
  3. Click Device status to see which devices have received the profile.

Possible Statuses

Status Meaning Action
Succeeded The profile was applied successfully. None needed.
Pending The device has not synced yet. Force a sync from the device (Settings > Accounts > Access work or school > Info > Sync) or from Intune (Devices > All devices > click device > Sync).
Error / Failed The profile could not be applied. Click on the device to see the error details. Common causes include conflicting policies or unsupported settings for the device's Windows edition.
⚠ If a profile conflicts with another profile (two profiles trying to set the same setting to different values), the device will report an error. Remove the conflicting setting from one of the profiles.
